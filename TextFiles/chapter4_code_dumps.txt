1.1 `Models/build_port_turnaround_dataset.py` (port turnaround training dataset)

Purpose (per script header)
 - Build a single training table for turnaround modelling by joining + cleaning port calls and voyage/vessel context.
 - No modelling/medians here; that happens in separate scripts.

Inputs (RAW)
 - Mandatory:
   - `port_calls_completed_asof_2025-12-31.csv`
   - `voyages_completed_asof_2025-12-31.csv`
   - `vessels_reference.csv`
 - Optional (used only for commodity enrichment):
   - `cargo_asof_2025-12-31.csv` (if missing → empty frame)
   - `commodity_reference.csv` (if missing → empty frame)
 - All CSVs are loaded from the selected customer raw directory, and columns are upper-cased on load.
   - Customer selection: `--customer` (defaults to the repo’s default customer in `utils/customer_paths.py`).

Step-by-step transformations (what happens in `main()`)
1) Load + normalize:
   - Read CSVs from `RAW/…`; immediately upper-case all column names (`df.columns = [c.upper() …]`).

2) Port calls table (`pc`) — select & clean (keys + label):
   - Select columns (create missing ones as NaN):
     - `PORT_CALL_ID`, `VOYAGE_ID`, `PORT_ID`, `TERMINAL_ID`, `IS_BALLAST`, `COMMODITY_ID`,
       `DAYS_IN_PORT`, `DAYS_STOPPAGES`, `DAYS_EXTRA_IN_PORT`
   - Coerce all selected columns to numeric via `pd.to_numeric(..., errors="coerce")`.
   - Hard filter on label quality:
     - Keep rows with `DAYS_IN_PORT` between 0.04 and 10.0 (≈ 1 hour to 10 days): `pc["DAYS_IN_PORT"].between(0.04, 10.0)`.

3) Voyages table (`voy`) — select & derive season:
   - Select columns (create missing as NaN):
     - `VOYAGE_ID`, `VESSEL_ID`, `VESSEL_TYPE_ID`, `ESTIMATED_VOYAGE_START_DATE`, `HAS_CANAL_PASSAGE`
   - Coerce numeric:
     - `VOYAGE_ID`, `VESSEL_ID`, `VESSEL_TYPE_ID`, `HAS_CANAL_PASSAGE`
   - Parse time:
     - `ESTIMATED_VOYAGE_START_DATE = pd.to_datetime(..., errors="coerce")`
   - Derived feature:
     - `MONTH_NO = ESTIMATED_VOYAGE_START_DATE.dt.month`

4) Vessels reference (`ves`) — select size proxies:
   - Select columns (create missing as NaN):
     - `VESSEL_ID`, `VESSEL_TYPE_ID`, `DWT_SUMMER`, `DRAFT_SUMMER`, `LOA`, `BEAM`
   - Coerce all selected columns to numeric.

5) Optional commodity enrichment (only if the optional files exist):
   - Cargo: keep only `VOYAGE_ID`, `COMMODITY_ID` (numeric coercion).
   - Commodity reference: keep only `COMMODITY_ID`, `COMMODITY_GROUP_ID`, `COMMODITY_CODE` (numeric coercion for `COMMODITY_ID`).

6) Joins (left joins; join keys listed explicitly):
   - Port calls → voyages:
     - `df = pc.merge(voy[["VOYAGE_ID","VESSEL_ID","VESSEL_TYPE_ID","MONTH_NO","HAS_CANAL_PASSAGE"]], on="VOYAGE_ID", how="left")`
     - Join key: `VOYAGE_ID`
   - Fill missing `VESSEL_TYPE_ID` using vessel reference:
     - `df = df.merge(ves[["VESSEL_ID","VESSEL_TYPE_ID", size…]].rename(VESSEL_TYPE_ID→VESSEL_TYPE_ID_VE), on="VESSEL_ID", how="left")`
     - Then: `df["VESSEL_TYPE_ID"] = df["VESSEL_TYPE_ID"].fillna(df["VESSEL_TYPE_ID_VE"])`, drop helper column.
     - Join key: `VESSEL_ID`
   - Optional: cargo → commodity:
     - Choose one cargo row per voyage: `drop_duplicates("VOYAGE_ID")` (after sorting).
     - Merge on `VOYAGE_ID`.
     - Prefer port-call `COMMODITY_ID` if present; else take from cargo (`fillna`).
     - Merge commodity reference on `COMMODITY_ID` to add group/code (left join).

7) Outlier trimming (group-wise tail trimming):
   - Group keys (only those present in the merged df): subset of `["PORT_ID","TERMINAL_ID","IS_BALLAST"]`.
   - For each group, compute `q05` and `q95` of `DAYS_IN_PORT` and keep rows inside [q05, q95].
   - Rows in groups where quantiles are NaN are kept (mask OR q05/q95 is NaN).

8) Final column selection (create missing columns as NaN, then reorder):
   - Core keep list includes:
     - keys: `PORT_CALL_ID`, `VOYAGE_ID`, `PORT_ID`, `TERMINAL_ID`, `IS_BALLAST`, `VESSEL_ID`, `VESSEL_TYPE_ID`
     - derived: `MONTH_NO`, `HAS_CANAL_PASSAGE`
     - vessel proxies: `DWT_SUMMER`, `DRAFT_SUMMER`, `LOA`, `BEAM`
     - label: `DAYS_IN_PORT`
     - optional enrichment: `COMMODITY_ID`, `COMMODITY_GROUP_ID`, `COMMODITY_CODE`
     - other port-call extras: `DAYS_STOPPAGES`, `DAYS_EXTRA_IN_PORT`

Outputs (DERIVED)
 - `port_turnaround_training.csv` (always written)
 - `port_turnaround_training.parquet` (best-effort; skipped if parquet engine missing)
 - `port_turnaround_training_counts.csv` (QA): group counts over (`PORT_ID`,`TERMINAL_ID`,`IS_BALLAST`)


1.2 `Models/build_sailing_time_dataset.py` (sailing-time training dataset)

Purpose (per script header)
 - Build a sailing-time training dataset with target `HOURS_PER_NM` (hours per nautical mile).

Inputs (RAW)
 - `sailing_time_voyages_asof_2025-12-31.csv` (mandatory; errors if missing)
 - `sailing_time_vessels_reference.csv` (mandatory; errors if missing)
 - `sailing_time_voyage_cargo_counts.csv` (optional; empty frame if missing)
 - Columns are upper-cased on load.

Outputs (DERIVED, under `DataSets/Derived/<customer>/sailing_time/`)
 - `sailing_time_training.csv`
 - `sailing_time_training.parquet` (best-effort)
 - `sailing_time_training_counts.csv` (QA group counts)
 - `sailing_time_dataset_log.jsonl` (append-only run summary)

Key thresholds
 - `HOURS_PER_NM_LOWER = 0.02`
 - `HOURS_PER_NM_UPPER = 5.0`

Step-by-step transformations
1) Configure output paths:
   - Derived folder is `DataSets/Derived/<customer>/sailing_time/` (created if missing).

2) Load voyages:
   - Read voyages CSV, uppercase columns.
   - Parse date: `VOYAGE_START_DATE = pd.to_datetime(VOYAGE_START_TS, errors="coerce")`.

3) Load vessels:
   - Read vessel CSV, uppercase columns.
   - Filter out “test” vessels:
     - If `VESSEL_NAME` exists, drop rows where it contains `"test"` (case-insensitive).

4) Load optional cargo-count features:
   - If missing: empty frame with columns `VOYAGE_ID`, `N_CARGO_ROWS`, `N_UNIQUE_CARGO`, `TOTAL_CARGO_QUANTITY`.

5) Join voyages with vessel reference (left join):
   - `df = voyages.merge(vessels[[...]], on=["VESSEL_ID","VESSEL_TYPE_ID"], how="left")`
   - Join keys: `VESSEL_ID`, `VESSEL_TYPE_ID`
   - The subset of vessel columns included:
     - `VESSEL_ID`, `VESSEL_NAME`, `VESSEL_TYPE_ID`, `DWT_SUMMER`, `DRAFT_SUMMER`, `LOA`, `BEAM`, `BUILT_YEAR`, `FLAG_ID`

6) Join optional cargo counts (left join):
   - `df = df.merge(cargo_counts, on="VOYAGE_ID", how="left")`
   - Join key: `VOYAGE_ID`

7) Feature engineering (`engineer_features`):
   - Target:
     - `HOURS_PER_NM = (DAYS_AT_SEA * 24.0) / MILES_TOTAL` (only if both positive; else NaN)
   - Derived features:
     - `BALLAST_FRAC = MILES_BALLAST / MILES_TOTAL` (if MILES_TOTAL > 0)
     - `MONTH_NO = VOYAGE_START_DATE.dt.month`
     - `YEAR = VOYAGE_START_DATE.dt.year`
     - `VOYAGE_YEAR_MONTH = VOYAGE_START_DATE.dt.to_period("M").astype(str)`
     - `HAS_CANAL_PASSAGE = numeric -> fillna(0) -> int`
     - `CANAL_COST = pd.to_numeric(..., errors="coerce")`
     - `VESSEL_AGE_YEARS = YEAR - BUILT_YEAR` (only if BUILT_YEAR exists)
   - Numeric coercions (if present):
     - `MILES_BALLAST`, `MILES_LOADED`, `MILES_TOTAL`, `DAYS_AT_SEA`, `DAYS_IN_PORT_TOTAL`, `DAYS_TOTAL`,
       `DWT_SUMMER`, `DRAFT_SUMMER`, `LOA`, `BEAM`,
       `TOTAL_CARGO_QUANTITY`, `N_CARGO_ROWS`, `N_UNIQUE_CARGO`

8) Quality filter (`filter_quality`):
   - Keep rows with `HOURS_PER_NM` within `[0.02, 5.0]` using `.between(...)`.

9) Write outputs (`write_outputs`) + logging (`log_summary`):
   - Write CSV and best-effort parquet.
   - QA counts: group-by `["VESSEL_TYPE_ID","HAS_CANAL_PASSAGE","MONTH_NO"]` (only columns that exist) → `..._counts.csv`.
   - Append run summary dict to `sailing_time_dataset_log.jsonl` in the same derived folder.

2) Optimiser interface — mapping table (CSV → derived feature → model/lookup → units → optimiser usage)
--------------------------------------------------------------------------------

Context
 - Thesis demo runner: `Models/run_thesis_optimizer_demo.py`
 - Candidate input CSVs for the demo are in `DataSets/Derived/Stena/SampleScenario/` (see `TextFiles/thesisDemoInputSchemas.txt`).
 - Predictive components are loaded from:
   - `DataSets/Derived/Stena/ML/sailing_time_features.json` + `Models/Artifacts/stena/sailing_time_dt.joblib`
   - `DataSets/Derived/Stena/ML/port_turnaround_features.json` + `Models/Artifacts/stena/port_turnaround_dt.joblib`
 - In the MIP, the central timing inequality is enforced via arc constraints:
   - `t_j >= t_i + (reposition_{v,i,j}) + (duration_i)`
   - Where `duration_i = sailing_days_i + turnaround_days_i` and `reposition_{v,i,j}` is estimated from port coordinates.

Mapping table
Format: input CSV column(s) → derived feature → model/lookup used → unit conversion → optimiser usage/parameter

Vessel availability & start node
 - `vessels_with_availability.csv:VESSEL_AVAILABLE_UTC` → `avail_ts(v)` → datetime parse (`pd.to_datetime(..., utc=True)` then tz-naive) → ts→days in solver (`(ts - t0)/86400`) → start-node time reference for arcs from `O_v`
 - `vessels_with_availability.csv:VESSEL_OPEN_PORT_ID` + `unallocated_voyages_detailed.csv:ORIGIN_PORT_ID` → reposition distance/time from vessel open port to first job origin → `ports_latlon.csv` haversine nm + default speed → `reposition_days = nm / default_speed_knots / 24` → contributes to `rho_{v,s_v,j}` and arc cost `time_weight * reposition_days`

Laycan time window (per voyage j)
 - `unallocated_voyages_detailed.csv:LAYCAN_START_UTC` → `a_j` → datetime parse + tz-naive → ts→days → hard lower bound constraint: `t_j >= a_j`
 - `unallocated_voyages_detailed.csv:LAYCAN_END_UTC` → `b_j` → datetime parse + tz-naive → ts→days → upper bound:
   - strict run: `t_j <= b_j` (`hard_laycan_end=True`)
   - relaxed run: `t_j <= b_j + late_j`, `late_j >= 0` with objective penalty (`hard_laycan_end=False`)
 - Fallback when laycans missing (demo prep step):
   - If `LAYCAN_START_UTC` or `LAYCAN_END_UTC` missing in the voyages table, `run_thesis_optimizer_demo.py:prep_dates()` sets them to `ESTIMATED_VOYAGE_START_DATE`.

Distance inputs → sailing-time estimator (per voyage j)
 - `MILES_TOTAL` (if present) else `MILES_DIRECT` else `MILES_BALLAST + MILES_LOADED` → `miles_total(j)` (the adapter will derive/fill) → used by `SailingTimeModelAdapter` → convert model output to days: `sailing_days_j = hours_per_nm_j * miles_total_j / 24` → contributes to `tau_j` (job duration)
 - `run_thesis_optimizer_demo.py:add_haversine_miles()`:
   - Uses `DataSets/Derived/Stena/Static/ports_latlon.csv` to compute `HV_DISTANCE_NM`
   - Fills `MILES_DIRECT` with `HV_DISTANCE_NM` when missing
   - (This improves sailing-time fallback and/or model feature completeness when `MILES_DIRECT` is sparse.)

Sailing-time estimator features (adapter-derived)
 - `VESSEL_TYPE_ID`, `HAS_CANAL_PASSAGE` → `VESSEL_TYPE_CANAL_KEY = VESSEL_TYPE_ID__HAS_CANAL_PASSAGE` → used if required by the trained pipeline
 - `VESSEL_TYPE_ID`, `MONTH_NO` → `VESSEL_TYPE_MONTH_KEY = VESSEL_TYPE_ID__MONTH_NO` → used if required by the trained pipeline
 - `LAYCAN_START_UTC` or `ESTIMATED_VOYAGE_START_DATE` → `MONTH_NO` → `SEASON` (winter/spring/summer/autumn) → used if required by the trained pipeline
 - Column variant mapping:
   - `DAYS_TOTAL_AT_SEA` → `DAYS_AT_SEA` (if training expects `DAYS_AT_SEA`)
   - `VOYAGE_CANAL_COST` → `CANAL_COST` (if training expects `CANAL_COST`)
 - Model/lookup used: `Models/Artifacts/stena/sailing_time_dt.joblib` (sklearn pipeline)
 - Output units: **days** (adapter contract) returned to optimiser.

Port-turnaround estimator features (adapter-derived)
 - `ORIGIN_PORT_ID` → `PORT_ID` (used as the turnaround “port” feature if `PORT_ID` not present)
 - `TERMINAL_ID`, `IS_BALLAST`, `VESSEL_TYPE_ID` → passed through / filled with NA if missing
 - `LAYCAN_START_UTC` or `ESTIMATED_VOYAGE_START_DATE` → `MONTH_NO` (if missing)
 - Optional derived keys if required by trained model metadata:
   - `PORT_TERMINAL_KEY = PORT_ID__TERMINAL_ID`
   - `PORT_IS_BALLAST_KEY = PORT_ID__IS_BALLAST`
 - Model/lookup used: `Models/Artifacts/stena/port_turnaround_dt.joblib` (sklearn pipeline)
 - Output units: **days** (turnaround duration); in arc building it is clipped to `[0.0, 10.0]`.
 - Optimiser usage: contributes to `tau_j` (job duration) via `duration_j = sailing_days_j + turnaround_days_j`.

Job-to-job reposition term rho_{v,i,j}
 - `DEST_PORT_ID` (from job i) + `ORIGIN_PORT_ID` (from job j) → `reposition_days(v,i,j)` → haversine nm + default speed → days → used as `rho_{v,i,j}` in time propagation and as `time_weight * reposition_days` in the arc cost
 - Lookup used:
   - `DataSets/Derived/Stena/Static/ports_latlon.csv` (if present); if missing or ports not found → reposition defaults to 0.0 (for some arcs) or a large sentinel (9999) used only for arc ranking.

Economic objective terms (per candidate arc)
 - `NET_FREIGHT` else `GROSS_FREIGHT` else `FREIGHT` → `revenue_val` → no conversion → used in arc cost component
 - Costs summed into `cost_val`:
   - `FREIGHT_COST`, `PORT_COST`, `HANDLING_COST`, `VOYAGE_CANAL_COST`, `FO_COST`, `DO_COST`, `VARIOUS_COST`, `RUNNING_COST`
 - `VARIOUS_REVENUE` is treated as revenue offset.
 - Arc economic term:
   - `cost_component = (cost_val - revenue_val - various_revenue) / cost_scale`
 - Total arc cost:
   - `cost = cost_component + time_weight * reposition_days (+ switch_penalty if preferred vessel mismatch)`
 - Optimiser parameter knobs (demo defaults):
   - `cost_scale = 1_000_000.0` (default in `solve_mip`)
   - `time_weight = 0.1` (default in `solve_mip`)
   - `switch_penalty = 0.5` (passed by thesis demo runner)

Preferred-vessel mapping (manual plan comparison)
 - `fleet_plan_manual.csv:VOYAGE_ID` + `fleet_plan_manual.csv:VESSEL_ID` → `preferred_vessels[voyage]=vessel`
 - Used for:
   - Filtering the demo to the same set of voyages/vessels as the manual plan
   - “Manual overlap” evaluation stats
   - Optional arc penalty (`switch_penalty`) if the optimiser assigns a different vessel to a voyage than the manual mapping
