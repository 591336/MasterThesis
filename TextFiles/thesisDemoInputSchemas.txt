Thesis demo — input schemas (sample scenario)

Purpose
 - This is a thesis-writing aid: an exact column inventory for the CSV inputs used by `Models/run_thesis_optimizer_demo.py`.
 - The descriptions below are based on how the current thesis demo pipeline reads/uses each column (including ML adapters and the MIP).

Paths (relative to `MasterThesis/`)
 - `DataSets/Derived/Stena/SampleScenario/vessels_with_availability.csv`
 - `DataSets/Derived/Stena/SampleScenario/unallocated_voyages_detailed.csv`
 - `DataSets/Derived/Stena/SampleScenario/fleet_plan_manual.csv` (used only for comparison + filtering + “preferred vessel” mapping)


1) `DataSets/Derived/Stena/SampleScenario/vessels_with_availability.csv`

Columns
 - `VESSEL_ID`: unique vessel identifier; used as the optimiser vessel key.
 - `VESSEL_NAME`: display name; not used by the optimiser (metadata only).
 - `VESSEL_TYPE_ID`: vessel class/type id; not used by the thesis demo optimiser (metadata only).
 - `DWT_SUMMER`: deadweight (summer); not used by the thesis demo optimiser (metadata only).
 - `DRAFT_SUMMER`: draft (summer); not used by the thesis demo optimiser (metadata only).
 - `LOA`: length overall; not used by the thesis demo optimiser (metadata only).
 - `BEAM`: vessel width; not used by the thesis demo optimiser (metadata only).
 - `VESSEL_OPEN_PORT_ID`: vessel’s starting/open port id; used to compute initial reposition time from vessel → first voyage origin.
 - `VESSEL_AVAILABLE_UTC`: earliest timestamp the vessel becomes available; used as the time reference for the first selected voyage in each vessel sequence.


2) `DataSets/Derived/Stena/SampleScenario/unallocated_voyages_detailed.csv`

Notes
 - This file provides the candidate “jobs” for the optimiser.
 - The optimiser uses timestamps (laycan/start), ports, and economic columns to build arcs and the objective.
 - The ML model adapters (sailing time + port turnaround) read from the same row; if a feature column is missing, the adapters fill it with NA (so it won’t crash, but the model may become less informative).

Columns
 - `VOYAGE_ID`: unique voyage/job identifier; used as the optimiser voyage key.
 - `VESSEL_ID`: legacy/prior assignment reference; not used by the thesis demo optimiser.
 - `VOYAGE_STATUS`: voyage status string/code; not used by the thesis demo optimiser.
 - `ESTIMATED_VOYAGE_START_DATE`: baseline timestamp for the voyage; used for sorting and as a fallback time window when laycans are missing.
 - `HAS_CANAL_PASSAGE`: binary/categorical canal indicator; used as a sailing-time model feature (when available).
 - `IS_BALLAST`: binary/categorical ballast indicator; used as a port-turnaround model feature (when available).
 - `CANAL_COST`: canal cost feature column (used by the sailing-time model adapter when present).
 - `MILES_DIRECT`: direct distance measure; used by sailing-time fallback logic and as an ML feature.
 - `MILES_BALLAST`: ballast miles; used to construct `MILES_TOTAL` in sailing-time adapter/fallback.
 - `MILES_LOADED`: loaded miles; used to construct `MILES_TOTAL` in sailing-time adapter/fallback.
 - `DAYS_TOTAL_AT_SEA`: observed/derived time-at-sea; mapped to `DAYS_AT_SEA` for the sailing-time model adapter when needed.
 - `DAYS_TOTAL_IN_PORT`: observed/derived time-in-port; not used by the thesis demo optimiser.
 - `DAYS_BALLAST`: observed/derived ballast time; not used by the thesis demo optimiser.
 - `DAYS_LOADED`: observed/derived loaded time; not used by the thesis demo optimiser.
 - `DAYS_WAITING`: observed/derived waiting time; not used by the thesis demo optimiser.
 - `ORIGIN_PORT_ID`: origin port id; used for vessel→voyage and voyage→voyage reposition estimates (and for haversine fill of missing `MILES_DIRECT` when port coordinates exist).
 - `DEST_PORT_ID`: destination port id; used for voyage→voyage reposition estimates (and for haversine fill of missing `MILES_DIRECT` when port coordinates exist).
 - `RP_BALLAST_ID`: routing/rp id (ballast); not used by the thesis demo optimiser.
 - `RP_LOADED_ID`: routing/rp id (loaded); not used by the thesis demo optimiser.
 - `TERMINAL_ID`: terminal id; used as a port-turnaround model feature (when available).
 - `LAYCAN_START_UTC`: laycan start timestamp; used as the lower bound in the optimiser time window constraint.
 - `LAYCAN_END_UTC`: laycan end timestamp; used as the upper bound in the optimiser time window constraint (hard or soft depending on the laycan policy).
 - `FREIGHT`: freight/revenue candidate; used as a revenue input (lower priority than NET/GROSS if those exist).
 - `GROSS_FREIGHT`: gross revenue; used as a revenue input (lower priority than NET if NET exists).
 - `NET_FREIGHT`: net revenue; preferred revenue input if present.
 - `FREIGHT_COST`: cost component; included in the optimiser arc economic cost term.
 - `PORT_COST`: cost component; included in the optimiser arc economic cost term.
 - `HANDLING_COST`: cost component; included in the optimiser arc economic cost term.
 - `VOYAGE_CANAL_COST`: cost component; included in the optimiser arc economic cost term.
 - `FO_COST`: fuel oil cost component; included in the optimiser arc economic cost term.
 - `DO_COST`: diesel oil cost component; included in the optimiser arc economic cost term.
 - `VARIOUS_COST`: cost component; included in the optimiser arc economic cost term.
 - `VARIOUS_REVENUE`: revenue component; included in the optimiser arc economic cost term (as a revenue offset).
 - `RUNNING_COST`: cost component; included in the optimiser arc economic cost term.
 - `RUNNING_COST_PER_DAY`: per-day running cost; not used by the thesis demo optimiser (the optimiser uses `RUNNING_COST`).


3) `DataSets/Derived/Stena/SampleScenario/fleet_plan_manual.csv`

Notes
 - Used for (1) filtering the demo to the same voyages/vessels, (2) comparing allocations (“manual overlap”), and (3) defining `preferred_vessels` (a voyage→vessel mapping) that the objective can penalise deviations from.

Columns
 - `FLEET_PLAN_VOYAGE_ID`: manual plan row id; not used by the thesis demo optimiser.
 - `FLEET_PLAN_ID`: manual plan group id; not used directly by the optimiser in the thesis demo.
 - `SEQUENCE`: manual sequence number within a vessel; not used by the thesis demo optimiser (comparison is done by voyage id and vessel id only).
 - `VESSEL_ID`: vessel id in the manual plan; used to (a) filter vessels and (b) compute the “preferred vessel” mapping and overlap metrics.
 - `VESSEL_NAME`: vessel name; not used by the thesis demo optimiser (metadata only).
 - `VOYAGE_ID`: voyage id in the manual plan; used to (a) filter voyages and (b) compute the “preferred vessel” mapping and overlap metrics.
 - `ESTIMATED_VOYAGE_START_DATE`: manual reference start date; not used by the optimiser (the optimiser reads timestamps from `unallocated_voyages_detailed.csv`).
