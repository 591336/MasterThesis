Questions for boss — parameters & business rules to calibrate the optimiser

The goal of this list is to replace “assumed” constants with business-grounded values (or at least plausible ranges)
so the thesis can justify parameter choices.


1) Objective priorities (what matters most?)
 - Is the primary KPI: maximise profit, maximise number of served voyages, or minimise operational disruption?
 - When those conflict, what’s the preferred trade-off (coverage vs cost vs service quality)?


2) Laycan semantics and penalties (critical)
 - Is laycan end a hard contractual constraint, or can we start after `b_j` with penalties?
 - If lateness is allowed:
   - What’s the “typical” penalty per day late (or per hour)?
   - Are there step penalties (e.g., 0–12h ok, 12–48h expensive, >48h unacceptable)?
   - Is there a hard maximum lateness tolerated operationally (e.g., 1–3 days)?
 - Does “lateness” mean arrival at load port, commencement of loading, or voyage start timestamp (what timestamp should be compared to laycan)?


3) Unserved / dropped voyage cost (opportunity cost)
 - If a voyage is left unserved, what is the penalty meant to represent?
   - Lost margin? contractual breach? reputational cost? charter substitution cost?
 - Is it reasonable to use one global penalty, or should it depend on voyage (cargo/customer class)?


4) Vessel usage / activation cost
 - Is there a fixed “cost” to using an additional vessel in the plan (crew/overhead, charter activation, coordination)?
 - Should the optimiser prefer fewer vessels if possible, even if it slightly reduces coverage/profit?


5) Repositioning costs and assumptions
 - Should ballast repositioning time be penalised in the objective beyond the economic costs already in the voyage rows?
 - Do you have typical ballast speed assumptions by vessel type (or a standard planning speed)?
 - Should canal passage affect repositioning feasibility/cost (or is it already captured elsewhere)?


6) Cost and revenue columns — what’s trustworthy?
 - In the voyage extracts, which revenue field should we prioritise: `NET_FREIGHT`, `GROSS_FREIGHT`, or `FREIGHT`?
 - Which cost components should be included (and which should be ignored) for planning:
   - `RUNNING_COST` vs `RUNNING_COST_PER_DAY` (which is correct / preferred)?
   - Are `FO_COST`/`DO_COST` reliable or duplicated elsewhere?
   - Is `VARIOUS_REVENUE` meaningful and stable enough to use?


7) Operational constraints missing in the thesis model (confirm what can be ignored)
 - Are there port/terminal restrictions (draft, LOA, beam, terminal compatibility) that matter for this use case?
 - Are there cargo constraints (compatibility, capacity, tank cleaning) that should be modelled, or can be ignored for thesis scope?
 - Are there “must-serve” voyages (hard requirements) vs optional voyages?


8) Evaluation: what is an acceptable plan?
 - What does “good enough” mean operationally for a generated plan:
   - maximum allowed laycan violations,
   - acceptable number of vessel changes relative to manual plan,
   - minimum coverage threshold,
   - runtime constraints (seconds/minutes).


9) Data definitions (to avoid mis-modelling)
 - Clarify timestamp meaning in exports:
   - What exactly is `ESTIMATED_VOYAGE_START_DATE`?
   - Are laycans defined at origin port, and do they refer to arrival vs start?
 - Turnaround definition:
   - Is turnaround “days in port at origin only”, “origin + destination”, or “total port time”?
